> **Summary**: GaussianEditor는 3D Gaussian Splatting(3DGS) 장면에서 편집할 대상을 추적하고, 2D 생성 모델의 안내를 받아 특정 영역을 수정하는 방법입니다. 핵심은 **Gaussian Semantic Tracing**을 통한 대상 선택, **Hierarchical Gaussian Splatting(HGS)**을 통한 편집 안정화, 그리고 객체 삭제·추가를 위한 **3D 인페인팅**입니다. 논문에서 보고한 일반적인 편집 시간은 실험 환경 기준 약 5~10분입니다.

## 1. Background & Motivation

### 기존 3D 편집의 어려움

**NeRF 기반 편집**: NeRF는 장면 정보를 신경망에 암시적으로 저장합니다. 따라서 장면의 특정 부분만 직접 선택하거나 변경하기 어렵고, 학습과 렌더링에도 시간이 걸립니다.

**3DGS 기반 편집**: 3DGS는 개별 가우시안에 접근할 수 있고 빠르게 렌더링됩니다. 하지만 편집할 객체에 해당하는 가우시안을 정확히 찾기 어렵습니다. 또한 2D 생성 모델이 제공하는 편집 신호가 매번 달라질 수 있어, 가우시안들을 그대로 최적화하면 결과가 불안정해질 수 있습니다.

### GaussianEditor의 해결 방식

논문은 편집할 가우시안에 의미 레이블을 붙여 학습 중에도 추적하고, 가우시안을 생성 시점에 따라 구분해 기존 구조의 변화를 제한합니다. 객체를 삭제하거나 새로 넣을 때는 별도의 3D 인페인팅 절차를 사용합니다.

## 2. Core Methodology

GaussianEditor의 전체 흐름은 **대상 선택, 2D 편집 신호 생성, 3D 가우시안 최적화**로 볼 수 있습니다. 객체 삭제와 추가에는 각각의 인페인팅 절차가 더해집니다.

### Gaussian Semantic Tracing: 편집 대상 추적

먼저 여러 시점에서 3DGS 장면을 렌더링하고, 2D 분할 모델로 대상의 마스크를 얻습니다. 그다음 렌더링에 기여한 가우시안으로 마스크 정보를 되돌려 보내 각 가우시안의 의미 레이블을 정합니다.

편집 도중 가우시안이 새로 생성되면 부모 가우시안의 레이블을 이어받습니다. 따라서 초기 2D 마스크를 고정해서 쓰는 방식과 달리, 가우시안의 수와 위치가 변해도 편집 대상을 계속 추적할 수 있습니다. 논문은 이 레이블을 이용해 대상 가우시안의 업데이트, 밀도 제어, 렌더링 범위를 선택합니다.

### Hierarchical Gaussian Splatting: 편집 안정화

HGS는 가우시안을 **생성된 밀도 제어 단계별 세대**로 구분합니다. 처음부터 있던 가우시안은 이전 장면의 구조를 유지하도록 더 강하게 제한하고, 나중에 생성된 가우시안은 새로운 세부 형태를 만들 수 있도록 상대적으로 자유롭게 둡니다.

여기서 **앵커(anchor)**는 공간에 따로 배치한 점이 아니라, 가우시안의 위치·크기·회전·불투명도·색상에 대해 기록한 **기준 상태**입니다. 현재 속성이 기준 상태에서 지나치게 벗어나지 않도록 앵커 손실을 적용합니다. 밀도 제어가 진행되면 기준 상태와 세대별 제약도 갱신됩니다.

### 2D 생성 모델의 편집 신호

GaussianEditor는 새로운 확산 모델을 제안하기보다 기존 2D 편집 방법을 안내 신호로 사용합니다. 논문 실험에는 Instruct-NeRF2NeRF 방식의 이미지 편집 안내와 Delta Denoising Score(DDS) 안내가 사용됩니다. 3DGS 장면을 렌더링한 결과가 편집 지시와 가까워지도록 가우시안을 최적화하고, 이때 의미 추적과 HGS가 편집 범위와 안정성을 조절합니다.

## 3. Editing Pipeline & Tasks

### 일반적인 장면 편집

1. 기존 3DGS 장면과 텍스트 편집 지시를 준비합니다.
2. 필요한 경우 2D 분할 결과를 가우시안의 의미 레이블로 옮겨 편집 대상을 정합니다.
3. 선택한 시점의 장면을 렌더링하고 2D 생성 모델에서 편집 신호를 얻습니다.
4. 편집 손실과 세대별 앵커 제약을 사용해 가우시안을 최적화합니다.

### 객체 삭제와 추가

| 작업 | 논문의 처리 방식 |
| ----- | ----- |
| **객체 삭제** | 의미 레이블에 해당하는 가우시안을 제거합니다. 삭제한 객체와 주변 장면의 경계에 생기는 결함은 2D 인페인팅 결과를 이용해 보정합니다. |
| **객체 추가** | 사용자가 지정한 시점의 2D 마스크와 텍스트 지시로 새 객체의 이미지를 생성합니다. 이를 거친 3D 메시로 변환한 뒤 가우시안으로 옮겨 HGS로 다듬고 기존 장면에 결합합니다. |

객체 추가에는 생성한 객체의 깊이와 기존 장면의 깊이를 맞춰 위치와 크기를 정하는 과정도 포함됩니다. 따라서 단순히 화면에 새 가우시안을 배치하는 것보다 단계가 많습니다.

## 4. Experiments & Results

### 편집 속도와 제어

논문의 실험은 단일 RTX A6000 GPU에서 수행되었습니다. 저자들은 일반적인 장면 편집에 약 **5~10분**, 객체 삭제에 약 **2분**, 객체 추가에 약 **5분**이 걸린다고 보고합니다. 이는 논문에 제시된 설정과 사례의 결과이며, 모든 장면에서 같은 시간이 걸린다는 뜻은 아닙니다.

정량 비교에서 Instruct-NeRF2NeRF, GaussianEditor-DDS, GaussianEditor-iN2N의 사용자 선호도는 각각 **15.45%**, **12.27%**, **72.28%**였습니다. CLIP Directional Similarity는 각각 **0.1600**, **0.1813**, **0.2071**로 보고되었습니다. 이 비교에서는 GaussianEditor-iN2N이 두 지표에서 가장 높았습니다.

### 각 구성 요소의 역할

논문의 제거 실험에서는 HGS가 없을 때 가우시안이 장면 전체로 퍼지거나 과도하게 늘어나 영상이 흐려지는 사례를 보입니다. 의미 추적이 없을 때는 의도하지 않은 영역까지 수정될 수 있습니다. 두 구성 요소는 각각 **최적화 안정성**과 **편집 영역 제어**를 담당합니다.

## 5. Conclusion & Insights

### 읽고 정리한 점

GaussianEditor는 3DGS의 빠른 렌더링과 개별 가우시안에 접근할 수 있다는 장점을 편집에 활용합니다. 이 논문에서 특히 중요한 점은 편집 대상의 레이블을 학습 과정 내내 유지하는 방법과, 새로 생성된 가우시안에 더 많은 변형 여지를 주는 HGS 설계입니다.

### 한계

논문은 2D 확산 모델이 복잡한 지시를 충분히 반영하지 못하면 3D 편집도 영향을 받는다고 설명합니다. 따라서 GaussianEditor의 결과는 선택한 2D 편집 안내의 성능에도 의존합니다.
